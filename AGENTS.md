# AGENTS.md — вход для любой нейросети/агента

Это **GandolaChat**: Discord-подобный мессенджер для компании друзей
(~10 активных, запас до ~50) со звонками, покером и сезонным компендиумом
по Dota 2 («Гандолиум»). Личный проект Papa-Gandola («хозяин»). Общение
в задачах, комментариях, коммитах и документах — **по-русски**.

Прежде чем что-то менять, прочитай:

1. **`docs/ARCHITECTURE.md`** — полное описание проекта: что это, как
   устроено, каждый модуль сервера, каждый экран клиентов, протокол
   WebSocket, API, модель данных, покер, звонки, пуши, Гандолиум,
   сборка, деплой, релизы, тесты, известные ловушки. Начинай с него.
2. **`CLAUDE.md`** — рабочие заметки предыдущего агента: история решений
   хозяина, «грабли» (уже случившиеся поломки и как их не повторить),
   бэклог. Более сжато и с жаргоном, но там самые свежие детали.
3. `README.md` — короткое описание для людей.

## Правила работы (коротко, подробности в docs/ARCHITECTURE.md)

- Цикл: задача от хозяина → ветка → Pull Request → хозяин мержит сам →
  деплой по таблице «что менял → что делать» (ARCHITECTURE.md, раздел
  «Деплой»). PR не создавать без явной просьбы хозяина о фиче; ветки
  других людей не трогать.
- `server/` → хозяин раскатывает `git pull && docker compose build server
  && docker compose up -d server`. Миграции Alembic накатываются сами.
- `client/` (десктоп) → поднять версию в `client/package.json` И
  `APP_VERSION` в `client/src/renderer/changelog.ts` (+ пункты в
  CHANGELOG там же, + `npm i --package-lock-only`); после мержа хозяин
  ставит тег `v2.x.x` → GitHub Actions собирает черновик релиза.
- `mobile/` → JS-правки уезжают по OTA сами после мержа в main; PWA
  хозяин пересобирает командой из таблицы деплоя; нативные изменения
  (новый модуль, разрешение, плагин, SDK) = новый APK и ОБЯЗАТЕЛЬНЫЙ
  бамп `runtimeVersion` в `mobile/app.json`.
- Никогда: менять `SECRET_KEY`; вешать TTL на сообщения (они вечные);
  убирать https/wss-фолбэки адресов в клиентах; запускать `npm audit fix
  --force`; пушить в чужую ветку.
- Перед каждым push проверяй, не смержен ли уже PR (хозяин мержит
  быстро): смержен → новая ветка от main и новый PR.
- Проверка: сервер — Python-тесты на живом Postgres (рецепт в
  ARCHITECTURE.md), десктоп — `npx vite build`, мобилка — `npx tsc
  --noEmit`; сквозные сценарии — Playwright против локального сервера.
- Меняешь поведение — обнови `docs/ARCHITECTURE.md` (и `CLAUDE.md`,
  если ведёшь его). Документ обязан описывать код, а не планы.
